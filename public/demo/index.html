Read the video transcript

TrustRail MENA checks network evidence before money moves. This is a working remittance wallet prototype, using live Nokia simulator calls, synthetic customers, and a clearly synthetic voice.

Aisha is sending five thousand dirhams from Dubai to a first time beneficiary in Pakistan. She confirms in the wallet. Its backend asks TrustRail for a recommendation. LangGraph coordinates Gemini planning, network checks, and institution owned policy. The wallet controls the payment. No real money moves.

The suspicious transfer returns HOLD. SIM Swap and Device Swap report recent changes. Location and roaming provide additional context. These signals justify review, not a claim of proven fraud. The trace shows the actual model, API evidence, and timing. The model cannot override policy.

A routine family transfer returns APPROVE with the two required checks. This means the wallet may continue under its own rules. TrustRail does not authorize or execute the payment.

Now keep the payment identical and change only the note. The customer is visiting her sister in Muscat and using her mobile there. We run again. Gemini adds a Roaming Status check. This is context sensitive tool selection, not three fixed presets. Travel alone is not treated as fraud.

What if a network signal is missing? The simulator intentionally makes Device Swap unavailable. TrustRail returns VERIFY, directing the wallet to stronger verification. It never substitutes invented safe evidence. Attempts are bounded, inside a seven second server budget.

Our first buyer is a remittance wallet. The proposed model is usage based pricing, with a pilot measuring false holds, verification completion, latency, and cost per decision. Real deployment still needs confirmed carrier coverage, consent, and local data processing. These are pilot requirements, not results already achieved. AI proposes checks. Policy decides. The wallet stays in control.
